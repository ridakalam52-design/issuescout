Draft reply

Thanks for the detailed report, @orjinameh — the curl transcripts make the failure mode very clear. Triage: this is a **docs bug** (P2, labels: api/docs/quickstart). The quickstart conflates two different base URLs: the self-hosted gateway prefix (`/v1`, e.g. `http://localhost:8000/v1`) and the hosted platform API (`/api/v1`, default `https://api.otari.ai/api/v1`, with region hosts like `eu.api.otari.ai` via `PLATFORM_BASE_URL`). The fix is to document `https://<region>.api.otari.ai/api/v1` in the quickstart and show the full region-specific URL when a key is created. No duplicate issues found. No repro was run in IssueScout's sandbox, since none was attached. Useful references: - [OtariChatGenerator docs](https://docs.haystack.deepset.ai/docs/otarichatgenerator) — confirms the hosted default includes `/api/v1` - [mozilla.ai blog: Otari Gateway with OpenCode](https://blog.mozilla.ai/use-the-otari-gateway-with-opencode) - [DeepWiki: base URL / region handling](https://deepwiki.com/search/what-base-url-does-the-hosted_3c746c37-6376-4559-af36-cbe8f36943a1) To scope the fix, could you share the exact quickstart page/section you followed (URL or heading)?
